## 4. DATA LAYER AND PROVIDER MAP
Internal units are SI (degC, m/s, Pa, mm, m). A `UnitFormatter` converts for display; default is US customary
(degF, mph, inHg, in, mi), switchable in Settings. Parse defensively: every NWS value can be null.

### 4.1 Region defaults (`RegionDefaults.kt`, editable)
- Home point (from the original spec): 38.9 N, -84.5 W. Presets: Florence KY (38.999, -84.627),
  Covington KY (39.084, -84.509), Downtown Cincinnati (39.103, -84.512). Optional "Use my location".
- NWS observation anchors: primary KCVG, secondary KLUK. WFO: ILN. NEXRAD site: KILN (Wilmington OH). Zone: America/New_York.

### 4.2 Core conditions, forecast, alerts - NWS API (keyless, primary)
Base `https://api.weather.gov`. Required headers on every request:
`User-Agent: NKYWeather/<version> (<contact email from Settings or a placeholder constant>)` and
`Accept: application/geo+json`.
- `GET /points/{lat},{lon}` -> cache 7 days: gridId, gridX, gridY, forecast, forecastHourly, forecastZone, county, radarStation.
- `GET /stations/{KCVG|KLUK}/observations/latest` -> temperature, dewpoint, windSpeed, windDirection, windGust,
  barometricPressure, relativeHumidity, heatIndex, windChill, visibility, textDescription.
  Reject observations older than 90 min or mostly null, then fall back KCVG -> KLUK -> nearest station from the points
  response. "Feels like" = heatIndex if present, else windChill if present, else temperature.
- `GET /gridpoints/{wfo}/{x},{y}/forecast` (7-day) and `/forecast/hourly` (hourly breakdown, 48 h shown).
- `GET /alerts/active?point={lat},{lon}`: parse id, event, severity, urgency, certainty, headline, description,
  instruction, effective, onset, expires, ends, senderName, areaDesc, geometry (may be null). Sort by severity then urgency.
- NWS has NO device push service. Do not claim push. Alert delivery = polling (section 7) with a "Checked X min ago" label.
  Document an optional v2 (small server polling NWS -> FCM topics per zone) in README only; do not build it.

### 4.3 Hourly / 15-minute fallback and wind grid - Open-Meteo (keyless)
`https://api.open-meteo.com/v1/forecast` with current, hourly, daily (sunrise/sunset not needed, computed locally),
`minutely_15=precipitation`, imperial units requested only if convenient (otherwise convert), `timezone=auto`.
Also used for an optional wind grid (comma-separated coordinates, 12x12 over the map viewport, throttled).
Show "Weather data by Open-Meteo.com (CC BY 4.0)" in About/attribution.

### 4.4 Minute-cast (next 60 minutes) - `NowcastProvider` interface, ordered fallback chain
1. Tomorrow.io v4 forecast with `timesteps=1m` (key optional) -> minutely precipitationIntensity + probability.
2. OpenWeather One Call 3.0 `minutely[]` (key optional; the plan needs a card on file, so treat it as opt-in).
3. Keyless fallback: Open-Meteo `minutely_15`, interpolated to a smooth 60-minute curve and LABELED
   "15-minute resolution" in the UI. Never present interpolated data as true minute-by-minute.
UI: bar/area chart of intensity over 60 min plus one plain-language sentence ("Light rain starting in 12 min,
ending around 2:40 PM") computed from the data. Intensity bands: none, drizzle, light, moderate, heavy, extreme.

### 4.5 Radar and map overlays - Iowa Environmental Mesonet + NASA GIBS (keyless)
RainViewer's free tier was cut back in 2026 (max zoom 7, no nowcast, no satellite, one color scheme, hashed frame
paths, personal-use only), so do NOT make it a dependency. Optional later: a `RadarTileSource` implementation for it.
- Reflectivity: IEM tile cache, composite layer `nexrad-n0q-900913` for "now" and its time-offset siblings
  (`...-m05m`, `...-m10m`, ... `-m50m`) for a 10-frame loop (about 50 min back, 5-min steps), via
  `https://mesonet.agron.iastate.edu/cache/tile.py/1.0.0/<layer>/{z}/{x}/{y}.png`.
- Single-site KILN: IEM RIDGE tiles (`ridge::ILN-<product>-<YYYYMMDDHHmm>`), reflectivity (N0B/N0Q) and base
  velocity (N0G/N0U). Verify product codes at runtime; if a frame 404s, skip it silently and keep the loop going.
- Satellite: NASA GIBS WMTS (EPSG:3857) GOES-East ABI GeoColor (visible) and Band 13 Clean IR, time `default` for latest.
- Wind streamlines: animated particle layer drawn from the Open-Meteo wind grid (stretch goal, phase 7 if time allows).
- All URL templates live in `ProviderEndpoints.kt` behind `RadarTileSource`. Preload frames as separate raster layers
  and cross-fade opacity for a smooth loop. Display required attributions (OpenStreetMap/OpenFreeMap, IEM/NOAA, NASA GIBS).
- Radar screen controls: layer chooser (Reflectivity, Velocity, Satellite Visible, Satellite IR, Wind), play/pause,
  scrub slider with frame timestamps, opacity, "KILN" site marker, alert polygons from section 4.2 when geometry exists.

### 4.6 Pollen - `PollenProvider` interface
Pollen.com has no official public API: do NOT scrape it. Providers: Tomorrow.io (treeIndex / grassIndex / weedIndex,
0-5) when a key is set; optional Google Pollen API (`pollen.googleapis.com`, key + billing) if the user enters one.
With no key: render a helpful empty card ("Add a free Tomorrow.io key in Settings to enable pollen") rather than fake data.
Cache 3 hours. Show Tree, Grass, Weed as three labeled gauges with category text.

### 4.7 Air quality
Primary when a key exists: AirNow API (`airnowapi.org`, current observation by lat/lon within 25 mi + forecast).
Keyless default: Open-Meteo Air Quality API (`air-quality-api.open-meteo.com`: us_aqi, pm2_5, pm10, ozone).
Show AQI number, EPA category and color, dominant pollutant, PM2.5, ozone, and one line of health guidance per category.
Attribute the source actually used.

### 4.8 Sun, moon and solar dynamics - pure Kotlin, no network
Implement `SolarCalculator` and `LunarCalculator` in `domain/astro/` (NOAA solar position algorithm or a faithful
SunCalc port). Outputs: sunrise, sunset, solar noon, civil/nautical/astronomical twilight, golden hour
(sun elevation -4 to +6 deg, morning and evening), blue hour (-4 to -8 deg), day length and delta vs yesterday,
current sun elevation/azimuth (feeds the sky shader), moon phase name, illuminated fraction, moonrise/moonset,
next new/full moon. Unit-test against NOAA reference values for the home point.

### 4.9 Secrets storage
Optional keys (Tomorrow.io, OpenWeather, AirNow, Google Pollen) are entered in Settings. Encrypt with an Android
Keystore-backed AES-GCM key (via Tink or direct `Cipher`), persist ciphertext in DataStore. Exclude from backups
(`dataExtractionRules`, `allowBackup=false`). Never log keys or full request URLs containing keys.

### 4.10 Cache TTLs
observations 10 min, forecast 30 min, hourly 30 min, nowcast 5 min, alerts 5 min, AQI 30 min, pollen 3 h,
points 7 d, radar frame list 5 min. Pull-to-refresh bypasses TTL but respects a 30-second minimum interval.

## 6. UX AND VISUAL SPECIFICATION (Material 3 Expressive, Android 17)
### 6.1 Design system (`ui/designsystem/`)
- `WeatherTheme` wraps `MaterialExpressiveTheme` with `MotionScheme.expressive()`, expressive shapes (`MaterialShapes`
  morphing for toggles/loading) and Roboto Flex typography.
- Palette policy (Settings: Auto / Always Monet / Always Weather): default is wallpaper dynamic color
  (`dynamicLightColorScheme` / `dynamicDarkColorScheme`). In Auto, when an active Severe/Extreme alert or a heavy
  precipitation/thunder condition exists, override with a condition-seeded scheme from MaterialKolor
  (`PaletteStyle.Expressive`): storm = deep navy + violet, clear day = warm gold, sunset = amber/rose, snow/ice = slate blue,
  fog = neutral gray, tornado/severe warning = high-contrast red/orange tertiary. Animate scheme changes with
  expressive spring specs. Respect system dark mode.
- Tactile glassmorphism: card surfaces use Haze frosted material over the sky background, progressive blur under the
  top bar and navigation bar, 1 dp translucent outline, and a tonal fallback (surface container at about 92% alpha) when
  blur is unavailable or battery saver is on. Text over glass must hold 4.5:1 contrast against the worst-case background.
- Sky background: one full-screen AGSL `RuntimeShader` composable `WeatherSky(condition, sunElevation, intensity, time)`.
  Uniform contract: `uniform float2 resolution; uniform float time; uniform float intensity; uniform float sunElevation;
  uniform half3 skyTop; uniform half3 skyBottom;` Layers: gradient sky driven by sun elevation, soft cloud noise,
  rain streaks, snow flakes, lightning flash, star field at night. Budget: one shader pass, no per-frame allocations,
  drive `time` with `withFrameNanos`, pause when the app is stopped, in PiP-minimized mode or when Reduce Motion is on
  (animator duration scale == 0), where it becomes a static frame.
- Hero temperature: variable-font weight/width and size interpolate with scroll via spring physics, applied only to
  the hero text (variable font changes are expensive).
- Haptics: `HapticFeedbackType` ticks when scrubbing radar frames and on alert expansion.

### 6.3 Adaptive behavior (Android 17 windowing)

- `NavigationSuiteScaffold` / `WideNavigationRail`: bar on compact, rail on medium, expanded rail on expanded widths.

## 7. BACKGROUND WORK, NOTIFICATIONS AND WIDGETS
- `AlertCheckWorker` (WorkManager periodic, 15 min minimum, CONNECTED network). Diff active alerts against stored ids;
  notify only for new alerts. Channels: "Tornado and Severe Warnings" (HIGH), "Watches and Advisories" (DEFAULT),
  "Rain Soon" (LOW, optional "rain starting in ~N min" from nowcast). Request POST_NOTIFICATIONS at a meaningful moment
  (after first alert opt-in), not on launch. Auto-cancel when the alert expires.
- "NWS Alert Pill" (replaces a lock-screen widget, which phones do not support): on API 36+, an ongoing notification for active
  Tornado/Severe Thunderstorm/Flash Flood warnings that requests promoted-ongoing treatment (`setRequestPromotedOngoing(true)`,
  `setShortCriticalText("TOR WRN")`, permission `POST_PROMOTED_NOTIFICATIONS`) so it shows as a status-bar chip and on the
  lock screen. Below API 36 it degrades to a normal high-priority notification. Settings toggle. Verify the platform symbol names
  against the SDK.
- Glance widgets with `GlanceTheme` (dynamic color), responsive size modes, tap -> deep link into the app:
  - 2x2 "Rain Gauge": ring showing next-60-minute precipitation, big temp, minutes until rain. Draw the ring into a small bitmap

  - 4x2 "Detailed Glance": current conditions, next 5 hours, alert chip.
  Refresh through `WorkManager` every 30 min and on data change via `updateAll`. Provide a generated preview and a resize-safe layout.
